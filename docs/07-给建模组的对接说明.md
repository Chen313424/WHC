# 给建模组的对接说明

> **这份文件可以直接复制发给建模组两位同学。**
> 导航组（你）需要他们交付的东西，以及为什么。

---

## 一、最重要的一件事：环境必须统一

**我们全队统一使用：**

```
Ubuntu 22.04  +  ROS 2 Humble  +  Gazebo Classic 11
```

**注意是 Gazebo Classic（旧版），不是 Gazebo Harmonic / gz-sim（新版）。**

### 为什么必须统一

**原因一：培训 PPT 教的就是 Gazebo Classic。**
PPT 第 11–26 页讲的 `Building Editor`、`Model Editor`、`Wall Inspector`、
`Edit → Save World As`、`simple shapes / custom shapes`——
**这些全部是 Gazebo Classic 独有的界面**，新版 Gazebo 根本没有这些工具。

**原因二：两个版本的 world 文件互不兼容。**
Classic 用的是 `libgazebo_ros_*.so` 系列插件，
新版用的是 `gz::sim::systems` 插件体系。
**如果建模组用 Classic 建的场地，导航组用新版打不开，反之亦然。**

**原因三：Gazebo Classic 装不上 Ubuntu 24.04。**
官方软件库里已经没有这个包了（实测 `packages.ubuntu.com/noble/gazebo` 返回"不存在"）。
所以必须用 Ubuntu 22.04。

> ⚠️ **如果你们已经装了别的版本，请换成 Ubuntu 22.04。**
> 否则你们做的场地，导航组加载不了，等于白做。

## 二、⚠️ 最关键的一个尺寸要求：激光雷达安装高度

> **激光雷达必须安装在离地面 50 cm 以下（建议 15–25 cm）。**

**为什么：**

培训 PPT 第 15 页建议围墙高度为 **50 cm**。
2D 激光雷达的扫描平面是一个**水平面**，
如果雷达装在 50 cm 以上，**激光从围墙上沿扫过去，扫不到墙**，
SLAM 就建不出地图，**整个导航方案直接失效**。

**这是整个项目里最容易忽略、后果最严重的一个尺寸。请务必确认。**

## 二·五、⚠️ 另一个实测踩到的坑：机器人模型里的相机

**实测发现（2026-10-02）：**

在 WSL 环境下，机器人模型如果带**相机传感器**，
`gzserver` 会在机器人刚生成成功之后**直接段错误崩溃**：

```
[INFO] Spawn status: SpawnEntity: Successfully spawned entity [turtlebot3_waffle]
[ERROR] [gzserver-1]: process has died [pid 925, exit code -11]      ← 段错误
```

`exit code -11` 表示 **SIGSEGV**。

**后果非常隐蔽：** 机器人显示"生成成功"，但 Gazebo 随即死掉，
`/scan` 和 `/odom` 话题完全不存在——**看起来像是插件没装或网络问题，很难往相机上想。**

**给建模组的建议：**

1. **先用不带相机的模型把导航链路调通**（激光雷达才是导航的核心传感器）
2. 需要相机时，先确认导航组的终端里执行过：
   ```bash
   export LIBGL_ALWAYS_SOFTWARE=1
   ```
   （软件渲染下相机通常能正常工作）
3. **最终交付前，务必在你自己的环境里跑一次**，确认加了相机之后
   gzserver 不会崩溃

> 这条已经写进 `docs/06-Gazebo与WSLg排障指南.md`，遇到时可以查。

## 三、请交付的 5 样东西（最迟 10-04）

| # | 交付物 | 格式 | 用途 |
|---|---|---|---|
| 1 | **场地 world 文件** | `.world` | 导航组的仿真入口 |

但**请务必在 10-04 前给到**，否则后面的建图、调参、录像全部顺延。

## 六·五、★ 时间紧张时的「最小可用场景」清单

> **背景：现在距提交只剩 5 天，距录制只剩 4 天。**
> 场地做不完，导航组就没法录"智慧社区巡检"的视频，**场景搭建完成度 15 分也会丢**。
>
> 所以这份清单的原则是：**先做出"能跑、能看、能拿分"的最小版本，再谈精细。**

### 第一优先：不做就没分（建议半天内完成）

| 项 | 最低要求 | 偷懒办法 |
|---|---|---|
| **4.2 m × 4.2 m 场地** | 地板 + 四面围墙（高 50cm、厚 0.5cm） | 用 Building Editor 直接画，见培训 PPT 第 14–15 页 |
| **车道线** | 画在地板贴图上即可 | 直接做一张 4.2×4.2 的 PNG 当地板材质（培训 PPT 第 26 页教了怎么改地板材质） |
| **红绿灯 ×2** | 一个立牌 + 三个圆点（红黄绿） | **不需要真的会变灯**：先做成静态贴图立牌。变灯效果导航组可以另外解决 |
| **人偶立牌** | 至少 14 个 | 就是"一块薄板贴一张人像 PNG"，培训 PPT 第 17–20 页有完整步骤 |
| **车牌 ×3 + 车背景** | 3 张车牌贴图 + 1 个背景板 | 尺寸按官方规格（§五），车牌随机生成 |
| **机器人模型** | 能跑就行 | **直接先用 TurtleBot3 的 `burger`**，你们不用做机器人，等场地做完再说 |

### 第二优先：有余力再做（不影响复赛得分）

- 街区（A/B）的实体块 —— 有更好，没有就用车道线围出来
- 指示牌、垃圾桶、楼宇标签 —— 复赛评分表里**不考这些**，是决赛内容
- 楼宇火灾/温度、站房仪表、电动车 —— **全是决赛内容，复赛不用做**

### ★ 可以大量复用 WHC 仓库的贴图

那份 Harmonic 的仓库里有 **30 张已经画好的 PNG**：

```
label_building_a/b/c/d.png     楼宇标签
label_street_a/b.png           街道标签
label_community / parking / spot_1/2/3 / start / station / ev / trash / visitor
plate_A / plate_B / plate_C / plate_ev          车牌
trash_recyclable / kitchen / hazardous / other  垃圾桶
sign_no_parking / no_straight / speed           指示牌
meter_temp / meter_pressure                     仪表
```

**PNG 贴图跟 Gazebo 版本无关，任何版本都能直接用。**
它们本来就是按官方示意图做的，**拿来做 Classic 场地的贴图完全没问题**。

> 也就是说：**你们的工作量主要在"摆位置和贴图"，不在"画素材"** —— 素材已经有了。

### 建议的推进顺序

```
① 先把 4.2×4.2 地板 + 四面墙搭出来，能进去看         ← 半天
② 把车道线画在地板贴图上                             ← 1 小时
③ 从 WHC 仓库拿贴图，做出人偶 / 车牌 / 红绿灯的立牌   ← 半天
④ 按示意图摆好位置，量出坐标填表交给导航组            ← 2 小时
⑤ 有余力再补：街区实体块、更多物料
```

**做完 ①②③④ 就已经能满足复赛的场景要求了。** ⑤ 可以不做。
