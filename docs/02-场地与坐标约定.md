## 二、场地结构分析（这是关键的好消息）

从示意图看，场地不是迷宫，而是：

```
                ┌─────────────────────────────┐
   起点/终点 →  │  [红绿灯1] [斑马线]         │  ← 右上角，向左行进
                │  ┌──────────────┐           │
                │  │   A 街区      │  ← 人偶   │
                │  └──────────────┘           │
                │  ┌──────────────┐           │
                │  │   B 街区      │  ← 人偶   │
                │  └──────────────┘           │
                │        [斑马线] [红绿灯2]    │
                └─────────────────────────────┘
                    ↑ 右侧一列：1/2/3 号停车位
```

**核心洞察：**

> **巡检路线 = 绕 A、B 两个矩形"街区"外侧的一条环形通路。**
> 起点和终点在右上角同一位置，跑完一圈回到原点。

这意味着导航问题被大幅简化：

| 结论 | 说明 |
|---|---|
| **不需要复杂拓扑规划** | 本质是一个带两个"岛"的环路，Nav2 轻松处理 |
| **通道宽度约 0.8–1.0 m** | TurtleBot3 waffle 直径 0.28 m，余量充足 |
| **可以硬编码站点序列** | 不用做动态任务分配 |
| **车道线合规可控** | 把 A/B 街区设为 costmap 禁区，规划器自然贴着车道走 |

**这是你们方案的最大优势，技术文档里要明确写出来。**

## 三、坐标系约定（三方必须统一）

### 3.1 世界坐标系（Gazebo / world 文件）

采用 **REP-103** 标准（ROS 官方坐标系规范）：

| 轴 | 方向 | 说明 |
|---|---|---|
| **X** | 向右 | 右手坐标系 |
| **Y** | 向上（俯视图） | |
| **Z** | 垂直向上 | |
| **原点** | **场地左下角** | 使全场坐标为 `x∈[0,4.2], y∈[0,4.2]`，全为正数，便于核对 |
| **单位** | 米 (m) | |
| **角度** | 弧度，逆时针为正；偏航角 `yaw`，0 = 朝 +X（向右） | |

**为什么原点放左下角（答辩素材）：**
> 采用场地左下角为原点，可使场地内所有物料坐标均落在第一象限（0–4.2 范围内），
> 便于与示意图逐一核对，也避免坐标系平移带来的符号错误。
> 姿态采用 REP-103 约定的右手坐标系，偏航角以 +X 轴为 0°、逆时针为正。

### 3.2 地图坐标系（SLAM 产物）

**注意：SLAM 生成的地图坐标系原点由机器人起始位姿决定，不等于世界坐标系。**

必须在 launch 文件里固定机器人出生点，保证每次建图/导航的地图原点一致：

| 约定 | 值 |
|---|---|
| 机器人出生点（世界坐标） | **待定，建议放在起点 (≈3.6, ≈3.7)，朝向 -X（朝左）** |
| 出生时朝向 `yaw` | **π (180°)** |

⚠️ 因为比赛要求"一键启动、不得人为干预"，**初始位姿不能靠人在 RViz 里点**，
必须写死在 launch 里。

## 五、巡检站点表（waypoints.yaml 模板）

> 这是导航组**最核心的配置文件**：车按这个顺序跑，每到一个站点停车、触发视觉识别。

**路线方向：从起点出发，沿顶部向左，逆时针绕行一圈回到起点。**

| # | 站点 ID | 站点名称 | 目标坐标 x | 目标坐标 y | 到点朝向 yaw | 停留动作 | 状态 |
|---|---|---|---|---|---|---|---|
| 1 | `start` | 起点 | | | | 无（出发） | ⬜ |
| 2 | `tl_1` | 红绿灯 1 停止线 | | | | **红灯等待** | ⬜ |
| 3 | `crowd_a` | A 街区人偶识别 | | | | 拍照 + 计数 | ⬜ |
| 4 | `crowd_a2` | A 街区补拍位 | | | | 拍照 | ⬜ |
| 5 | `crowd_b` | B 街区人偶识别 | | | | 拍照 + 计数 | ⬜ |
| 6 | `crowd_b2` | B 街区补拍位 | | | | 拍照 | ⬜ |
| 7 | `tl_2` | 红绿灯 2 停止线 | | | | **红灯等待** | ⬜ |
| 8 | `park_3` | 3 号停车位车牌识别 | | | | 拍照 + OCR | ⬜ |
| 9 | `park_2` | 2 号停车位车牌识别 | | | | 拍照 + OCR | ⬜ |
| 10 | `park_1` | 1 号停车位车牌识别 | | | | 拍照 + OCR | ⬜ |
| 11 | `start` | 回到终点 | | | | 结束播报 | ⬜ |

**用法说明：**
- 站点坐标 = 车体**中心**要到达的位置，不是物料位置。停靠点要离物料 ~0.3–0.5 m，保证相机视野完整。
- `到点朝向 yaw` 决定车头对准哪边。**这是视觉识别成败的关键**，必须和视觉组一起定。
- 站点数量可以增减。**少于 6 个站点会被评审认为"巡检不完整"，建议 8–12 个。**
