## 三·五、✅ 已解决：tl_1（红绿灯1停止线）导航失败 → 实为测试残留障碍

**结论（2026-10-07 排查完毕）：不是导航 bug，是 Q11 动态障碍测试的残留物。**

**现象：**

- 巡检跑完整一圈时，**只有 tl_1 一站失败**——3 次尝试（2 次 60s 超时 + 1 次 ABORT）后跳过，其余 10 站全部到达。
- 单独复测：直接发 `NavigateToPose` 到 tl_1 目标点 `(-0.1, 1.3)`，yaw 取 +π 和 -π **都超时**。

**排查过程（真因）：**

1. 探针读代价地图：`(-0.1,1.3)` 在 local/global costmap 里都是 **99（OCC 占用）**，
   而 `(-0.3,1.3)` 停止线处是 FREE——说明目标点**正被某个物理障碍占据**。
2. 直接读静态地图 `community_map.pgm`：该点像素 = 254（FREE），排除建图残留。
3. `gz model --list` 发现一个 **`obstacle_test` 模型**——是 Q11 动态障碍测试时 spawn 的箱子，
   位置 `(0, 1.3)`，0.4 m 宽，正好压在 tl_1 目标点 `(-0.1,1.3)` 上。
4. `gz service /world/smart_community/remove` 删除该障碍后，代价地图该点恢复 FREE，
   tl_1 单点复测 **SUCCEEDED（status=4）**。

**复验（clean run 完整一圈，2026-10-07）：**

- 删除障碍后重跑整圈巡检：**11/11 站全部到达、0 失败**，一圈仿真时钟 156 s（墙钟 445 s，RTF≈0.35）。
- 有 3 个「大角度转向站」（start / zone_a / finish）首试触发 60 s 墙钟超时、**重试即通过**，
  属 RTF 0.34 的慢速伪影，非真 bug（见 [05](05-复赛技术方案文档（初稿）.md) §4.6 注意事项 3）。

> **教训 / 预防：** 动态障碍测试（Q11）spawn 的障碍块，测完必须删除，否则会留在场地上
> 挡住后续巡检/录制的站点。建议在测试脚本末尾加 `gz service remove` 清理。
>
> **导航配置与 11 个站点坐标均无需改动。**
