# Nav2 调参速查手册

> **用法：** 遇到现象 → 在下表找到对应行 → 按顺序改参数 → 重新跑一次看变化。
>
> **调参铁律：一次只改一个参数。** 同时改三个，你永远不知道是哪个起了作用。
>
> ⚠️ 本手册里的参数都在 `src/community_nav/config/nav2_params.yaml` 里。

---

## 零、调参前必须确认的三件事

**这三件事不对，后面怎么调都是白费。**

| # | 检查项 | 命令 | 正确表现 |
|---|---|---|---|
| 1 | TF 树完整 | `ros2 run tf2_tools view_frames` | 生成 PDF，含 `map → odom → base_footprint → base_scan` |
| 2 | 激光与地图贴合 | 看 RViz | 红色激光点**紧贴**地图上的墙线，不偏移、不错位 |
| 3 | 里程计方向正确 | `ros2 topic echo /odom --field twist.twist.linear` | 车往前走，`x` 为正；原地左转，`angular.z` 为正 |

**如果第 2 条不对**（激光整体偏离墙线），那是**定位问题**不是导航问题，
先去看第五节的"定位类问题"，不要动规划器的参数。

## 一、规划类问题

### 1.1 规划器报 `Failed to create plan` / `Unable to find a valid path`

**最常见、也最容易被误判为"地图坏了"的问题。**

| 顺序 | 可能原因 | 参数 | 怎么改 |
|---|---|---|---|
| ① | **膨胀半径把车道堵死了** | `global_costmap.inflation_layer.inflation_radius` | 从 0.28 往下试 0.25 / 0.22。**先确认车道实际宽度** |
| ② | 机器人半径设太大 | `robot_radius` | TurtleBot3 waffle 用 0.22；自研车按实际外接圆重算 |
| ③ | 起点或终点在障碍里 | — | 在 RViz 里看目标点是不是落在黑色区域上 |
| ④ | 未知区域被当成障碍 | `global_costmap.track_unknown_space` | 如果地图边缘有大片灰色（未知），改成 `false` 试一次 |
| ⑤ | 代价惩罚太高 | `planner_server.GridBased.cost_penalty` | 从 5.0 降到 3.0 试 |

**判断调对了：** RViz 里出现一条绿色的全局路径，且**走在车道中间**。

---

### 1.2 路径贴边 / 抄近路压线

| 顺序 | 参数 | 怎么改 | 说明 |
|---|---|---|---|
| ① | `planner_server.GridBased.cost_penalty` | 5.0 → 8.0 / 12.0 | 越大越"宁可绕远也不贴边" |
| ② | `inflation_layer.cost_scaling_factor` | 6.0 → 8.0 | 代价衰减更快，车道中心更低代价 |
| ③ | 上面两个都不够 | — | **说明需要 KeepoutFilter 掩膜**，见 `docs/02-场地与坐标约定.md` 第七节 |

⚠️ 注意：**2D 激光雷达看不到地面上的车道线**。
如果车道边界没有物理墙体，光靠调参数**不可能完全解决压线**。
这时要么加掩膜，要么在 Gazebo 里把车道线建成几厘米高的矮墙。

---

### 1.3 路径在 RViz 里不显示 / 只显示一小块

| 参数 | 改成 |
|---|---|
| `global_costmap.always_send_full_costmap` | `True` |
| `local_costmap.always_send_full_costmap` | `True` |

## 二、控制类问题（车动起来之后）

### 2.1 车走 S 形 / 左右摆动

| 顺序 | 原因 | 参数 | 怎么改 |
|---|---|---|---|
| ① | 前视距离太短，盯着脚下走 | `FollowPath.lookahead_dist` | 0.30 → 0.40 |
| ② | 速度太快，来不及修正 | `FollowPath.desired_linear_vel` | 0.18 → 0.13 |
| ③ | 角速度上限太高 | `FollowPath.max_angular_vel` | 0.8 → 0.5 |
| ④ | 路径本身抖 | `planner_server.GridBased.smoother.w_smooth` | 0.3 → 0.5 |

**判断调对了：** 车沿直线走时轨迹是直的，不左右画龙。

---

### 2.2 车转弯时甩出去 / 冲出车道

| 参数 | 怎么改 |
|---|---|
| `FollowPath.desired_linear_vel` | 调小（0.18 → 0.12） |
| `FollowPath.regulated_linear_scaling_min_radius` | 0.5 → 0.8（更早开始减速） |
| `FollowPath.max_linear_accel` / `max_linear_decel` | 0.4 → 0.25（加减速更柔和） |

---

### 2.3 车冲过停止线 / 到点刹不住

| 参数 | 怎么改 | 说明 |
|---|---|---|
| `FollowPath.use_approach_linear_velocity_scaling` | 确认是 `true` | 接近目标自动减速 |
| `FollowPath.approach_velocity_scaling_dist` | 0.45 → 0.6 | 更早开始减速 |
| `FollowPath.desired_linear_vel` | 0.18 → 0.12 | 整体降速 |

---

### 2.4 车到不了点，在原地来回微调

| 顺序 | 参数 | 怎么改 |
|---|---|---|
| ① | `general_goal_checker.yaw_goal_tolerance` | 0.12 太严就放到 0.15 / 0.20 |
| ② | `general_goal_checker.xy_goal_tolerance` | 0.08 太严就放到 0.10 |
| ③ | `FollowPath.min_angular_vel` | 0.15 → 0.25（原地小角度转不动就是它太小） |

⚠️ **但注意：`yaw_goal_tolerance` 直接决定视觉能否拍到目标。**
车头偏 15° 以上车牌就会斜出视野。所以**不要为了图省事把它放得很宽**，
优先检查是不是定位或路径本身的问题。

---

### 2.5 车卡住不动 / 原地转圈

| 顺序 | 检查 | 说明 |
|---|---|---|
| ① | `ros2 topic echo /cmd_vel` 有没有输出 | 没输出 = 控制器没在工作，看第二节 |
| ② | `progress_checker.required_movement_radius` | 当前 0.15 / 8.0 秒。太严会误判卡死 |
| ③ | 局部代价地图 | RViz 里看车周围是不是被红色填满了（膨胀太大） |
| ④ | 恢复行为 | 看终端有没有 `Spin` / `BackUp` 的日志 |

---

### 2.6 恢复行为把车顶到墙上

| 参数 | 怎么改 |
|---|---|
| `behavior_server.max_rotational_vel` | 0.8 → 0.5 |
| `behavior_server.min_rotational_vel` | 0.15 → 0.10 |
| `behavior_server.simulate_ahead_time` | 2.0 → 1.0 |

> 默认的恢复行为参数是针对几十米级室内环境设计的，
> 在 0.8 m 宽的车道里会"越恢复越糟"。

## 三、建图类问题（SLAM 阶段）

| 症状 | 原因 | 参数 | 怎么改 |
|---|---|---|---|
| **墙体重影 / 双层** | 回环检测没生效，或里程计漂移大 | `do_loop_closing` | 确认是 `true`；确认走完了完整一圈 |
| 同上 | 扫描匹配太稀疏 | `minimum_travel_distance` | 0.15 → 0.10 |
| **场地中央出现孤立黑点（鬼影）** | 激光噪声被当成障碍 | `max_laser_range` | 4.5 → 3.5 |
| 同上 | 实时障碍层距离太远 | `raytrace_max_range` | 3.5 → 2.5 |
| **墙角糊成一团** | 转弯时匹配不足 | `minimum_travel_heading` | 0.15 → 0.10 |
| **地图刷新很慢** | 更新间隔太长 | `map_update_interval` | 1.0 → 0.5 |
| **地图边界缺一块** | 没走到那里 | — | 重新走一遍，贴边走 |

**建图验收标准：**
1. 墙线细而直，不是一团糊
2. 绕场一周回起点后，起点附近墙体**没有重影**
3. 场地中央没有孤立黑点

## 四、巡检业务类问题

| 症状 | 检查 |
|---|---|
| **车到点了但不停** | `community_waypoints.yaml` 里该站的 `action` 是不是 `capture`；`dwell` 是不是 0 |
| **同一站点跑了两遍** | 检查站点表有没有重复 id |
| **红绿灯不停车** | ① `action` 是不是 `traffic_light` ② `ros2 topic echo /traffic_light/state` 有没有数据 ③ 视觉组发的字符串是不是正好是 `RED`/`GREEN`（大小写敏感） |
| **红灯停了但绿灯不走** | 视觉组有没有发 `GREEN`；`light_wait_timeout` 是不是到了（默认 60 秒） |
| **整圈跑不完** | 看终端里哪一站报 `导航失败已超过重试次数，将跳过` |
| **节点一启动就退出** | 站点表路径不对，看报错里的提示 |

**调试单个站点：**
```bash
# 只跑巡检节点，手动在 RViz 里点目标点，对比坐标
ros2 run community_patrol patrol_node --ros-args \
  -p waypoints_file:=$HOME/smart_community_ws/src/community_nav/config/community_waypoints.yaml \
  -p autostart:=false
```

## 五、定位类问题（AMCL）

| 症状 | 原因 | 参数 | 怎么改 |
|---|---|---|---|
| **激光与地图整体错位** | 初始位姿不对 | `initial_pose` | 确认建图与导航两次运行的**机器人出生点完全一致** |
| **定位跳变 / 闪烁** | 粒子太少 | `min_particles` / `max_particles` | 300/1500 → 500/2000 |
| **走到某处定位突然丢失** | 该处特征太少 | `laser_likelihood_max_dist` | 1.0 → 1.5 |
| **转弯时位姿漂移明显** | 更新阈值太松 | `update_min_a` | 0.10 → 0.05 |
| **定位收敛很慢** | 粒子撒得太散 | `sigma_hit` | 0.2 → 0.1 |

**判断定位是否可靠：**
在 RViz 里看 **红色激光点是否紧贴地图上的墙线**。
贴合 = 定位正确；整体偏移 = 位姿错了；忽远忽近 = 粒子太少。

## 六、调参的正确顺序

**不要一次全开。按这个顺序，每一步都验证通过再进下一步：**

```
① 只启动 Gazebo + 机器人
   → 验证：/scan 有数据、TF 树完整、里程计方向对

② 启动 slam_toolbox 建图
   → 验证：RViz 里能看到墙的轮廓

③ 存图 → 加载地图 + AMCL
   → 验证：激光点紧贴地图墙线

④ 单点导航（先在 RViz 里手动点一个点）
   → 验证：能规划出路径、能走到、不撞墙

⑤ 多点巡检（FollowWaypoints）
   → 验证：能按顺序跑完所有站点

⑥ 加红绿灯停车
   → 验证：红灯停、绿灯走

⑦ 加车道线合规（掩膜或矮墙）
   → 验证：全程不压线
```

**每一步都录一小段屏。** 最后剪辑视频时，这些素材直接用得上，
不用为了录像再重新跑一遍。

## 八、求助时该提供什么

调不出来时，把下面这些一起发出来，我能快速定位：

```bash
# 1) 当前参数（关键几项）
ros2 param get /controller_server FollowPath.desired_linear_vel
ros2 param get /global_costmap global_costmap inflation_layer.inflation_radius
ros2 param get /amcl laser_max_range

# 2) TF 树
ros2 run tf2_tools view_frames

# 3) 节点列表（看有没有起不来的）
ros2 node list

# 4) 报错的那一段日志（最后 30 行）
```

**加上 RViz 的截图**（能看到代价地图、激光点、路径的那种）—— 一张图胜过一百行日志。
