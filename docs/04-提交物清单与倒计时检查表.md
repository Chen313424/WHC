## 五、视频压缩：怎么压到 300MB 以内又不糊

**先算清楚：** 10 分钟 → 300MB → 约 **4000 kbps 总码率**。
屏幕录制画面变化少、压缩率极高，1080p 通常远低于这个值。

### 推荐做法（保持 1080p，代码清晰）

```bash
ffmpeg -i 原始视频.mp4 \
  -c:v libx264 -crf 24 -preset slow \
  -pix_fmt yuv420p \
  -vf "scale=1920:-2" \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  "【队伍名称】-智慧社区复赛综合展示视频.mp4"
```

**参数解释（答辩时可以讲）：**
- `-crf 24`：恒定质量模式，数值越大压缩越狠（18 几乎无损，28 明显糊）。**代码画面建议 22–24**
- `-preset slow`：编码更慢但体积更小
- `-pix_fmt yuv420p`：保证各种播放器都能播
- `-movflags +faststart`：把索引放到文件头，便于在线播放

### 如果还是超了

```bash
# 精确控制到指定大小（两遍编码），例如目标 280MB / 10分钟 ≈ 3700kbps
ffmpeg -y -i 原始视频.mp4 -c:v libx264 -b:v 3500k -preset slow -pass 1 -an -f mp4 /dev/null
ffmpeg -y -i 原始视频.mp4 -c:v libx264 -b:v 3500k -preset slow -pass 2 \
  -c:a aac -b:a 128k -pix_fmt yuv420p -movflags +faststart 输出.mp4
```

### 录制建议

| 项 | 建议 |
|---|---|
| 分辨率 | **1920×1080**（代码必须看得清） |
| 帧率 | 30fps 足够（25/30 都行，不要 60） |
| 录音 | **一定要单独录清晰人声**，别用环境麦 |
| 编码 | 录屏软件用 H.264 直出，别录成无损 |
| 分屏 | Gazebo 左 + RViz 右，各占一半；或用画中画 |

## 七·五、★ 提交前必须替换掉的所有占位符

文档里凡是写着 **`【待填】`** 的地方，都是留给你填**真实实测数据**的。
**一个都不能留在提交的 PDF 里** —— 评审看到占位符，会直接怀疑内容是编的。

### 一键找出所有残留

```bash
cd <工作区根目录>
grep -rn "【待填" docs/ --include="*.md" \
  | grep -vE "不要编|必须换成|换成真实|提交前逐条|留给你填|grep -rn"
```

> **为什么要加后面那个 `grep -vE`：** 本说明文件和几处"不要编"的提醒文字里
> 也含这两个字，不过滤掉的话命令永远不会输出为空。
> **排除之后的输出应为空**（说明没有残留的 `【待填】` 数据位）。
> 如果还有输出，那就是漏填的占位符。
