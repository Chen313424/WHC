## 一、版本决策：Ubuntu 24.04 决定 ROS 2 版本

ROS 2 和 Ubuntu 是**强绑定**的，不能乱配：

| Ubuntu | 代号 | 对应 ROS 2 | 仿真器 | 说明 |
|---|---|---|---|---|
| 24.04 LTS | `noble` | **Jazzy** | Gazebo Harmonic | ⭐ **本项目使用** |
| 22.04 LTS | `jammy` | Humble | Gazebo Classic 11 | 旧组合，已弃用 |

### 为什么全队统一到 24.04 + Jazzy + Harmonic（答辩素材）

1. **仿真组的场景与机器人就是按 Harmonic 搭的**：`smart_community_sim` 包里的
   world 文件、`robot.xacro`、红绿灯插件用的都是 `gz-sim` 的 `gz::sim::systems`
   插件体系，只有 Gazebo Harmonic 能加载。
2. **ROS 2 Jazzy 与 Ubuntu 24.04 LTS 强绑定**，是官方长期支持组合，支持周期到 2029。
3. **Gazebo Classic 已停止维护**，且官方软件库里已没有 24.04 上的 `gazebo` 包
   （实测 `packages.ubuntu.com/noble/gazebo` 返回 "Package not available"）。

### 先确认你的 Ubuntu 版本

```bash
. /etc/os-release && echo "版本: $VERSION 代号: $VERSION_CODENAME"
```

- 输出 `代号: noble` → 直接往下走
- 输出 `代号: jammy` → 需要换成 Ubuntu 24.04（见下）

### 如果你现在是 Ubuntu 22.04 / 没有 24.04

在 **Windows PowerShell**（不是 Ubuntu 里）执行：

```powershell
# 先看有哪些可装的发行版
wsl --list --online

# 安装 Ubuntu 24.04
wsl --install -d Ubuntu-24.04
```

装完后开始菜单会出现 `Ubuntu-24.04`，打开它设置用户名密码即可。

### 如果 `wsl --list --online` 报错（国内常见）

典型报错：

```
无法从 'https://raw.githubusercontent.com/microsoft/WSL/master/distributions/DistributionInfo.json'
提取通讯组列表。与服务器的连接被重置
错误代码: Wsl/0x80072eff
```

**原因：** `wsl --list --online` 和 `wsl --install -d` 都需要访问
`raw.githubusercontent.com` 获取发行版列表，该域名在国内被重置。

**这时直接用下面的方式手动导入，不依赖微软的在线列表。**

**方案 A：手动导入官方镜像（推荐）**

在 **Windows PowerShell** 里执行：

```powershell
# 1) 下载 Ubuntu 24.04 的 WSL 镜像（约 350 MB）
#    ★ 用清华镜像，国内速度快
curl.exe -L -o "$env:TEMP\ubuntu2404.tar.gz" `
  https://mirrors.tuna.tsinghua.edu.cn/ubuntu-cloud-images/wsl/noble/current/ubuntu-noble-wsl-amd64-ubuntu24.04lts.rootfs.tar.gz

# 2) 建一个存放目录（放 D 盘，别占 C 盘）
mkdir D:\WSL\Ubuntu-24.04 -Force

# 3) 导入为新的 WSL 发行版
wsl --import Ubuntu-24.04 D:\WSL\Ubuntu-24.04 "$env:TEMP\ubuntu2404.tar.gz" --version 2

# 4) 启动
wsl -d Ubuntu-24.04
```

**验证：**

```bash
. /etc/os-release && echo "代号: $VERSION_CODENAME"
```

必须输出 `代号: noble`。

**镜像地址备选（清华不通时换上海交大）：**

```
https://mirror.sjtu.edu.cn/ubuntu-cloud-images/wsl/noble/current/ubuntu-noble-wsl-amd64-ubuntu24.04lts.rootfs.tar.gz
https://cloud-images.ubuntu.com/wsl/noble/current/ubuntu-noble-wsl-amd64-ubuntu24.04lts.rootfs.tar.gz
```

> ⚠️ `wsl --import` 装出来的发行版**默认以 root 身份登录**，没有普通用户。
> 对装 ROS 2 没有影响（我们本来就需要 `sudo`），若想要普通用户可执行：
>
> ```bash
> adduser 你的用户名
> usermod -aG sudo 你的用户名
> ```

**方案 B：从微软商店装（图形界面）**

打开「Microsoft Store」，搜索 `Ubuntu 24.04`，选择 **Ubuntu 24.04 LTS** 安装。

## 二、WSL 性能配置（Windows 侧，只做一次）

WSL2 默认会吃掉很多内存。Gazebo + RViz + Nav2 要同时跑，需要给它够用的资源，但也别让它把 Windows 拖死。

在 **Windows** 里新建/编辑文件 `C:\Users\<你的用户名>\.wslconfig`（注意文件名前面有个点）：

```ini
[wsl2]
memory=8GB
processors=4
swap=4GB
```

**数值怎么定：**
- `memory`：取你物理内存的一半左右。16GB 内存 → 8GB；8GB 内存 → 4GB
- `processors`：取你 CPU 逻辑核心数的一半

改完后在 Windows PowerShell 里重启 WSL 生效：

```powershell
wsl --shutdown
```

> **为什么这么做（答辩素材）：** WSL2 是一个轻量级虚拟机，默认会动态占用大量内存。
> 仿真 + 导航栈同时运行峰值内存较高，需要预留足够资源，否则会出现节点被 OOM Killer
> 杀掉、Gazebo 突然崩溃等难以定位的问题。

## 四、配置 ROS 2 软件源（清华镜像）

官方源在国内很慢，用清华镜像。

### 4.1 导入 GPG 密钥

```bash
curl -sSL https://mirrors.tuna.tsinghua.edu.cn/rosdistro/ros.key \
  | sudo gpg --dearmor -o /usr/share/keyrings/ros-archive-keyring.gpg
```

**验证是否成功：**

```bash
ls -l /usr/share/keyrings/ros-archive-keyring.gpg
```

应该看到一个大小约 1–3 KB 的文件。如果是 `0` 字节，说明下载失败，换成官方源：

```bash
curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  | sudo gpg --dearmor -o /usr/share/keyrings/ros-archive-keyring.gpg
```

> **如果这两条都失败**（raw.githubusercontent.com 在国内经常被墙），
> 第三方案：直接从 Ubuntu 密钥服务器拉
> ```bash
> sudo apt install -y gnupg
> gpg --keyserver keyserver.ubuntu.com --recv-keys C1CF6E31E6BADE8868B172B4F42ED6FBAB17C654
> gpg --export C1CF6E31E6BADE8868B172B4F42ED6FBAB17C654 | sudo tee /usr/share/keyrings/ros-archive-keyring.gpg > /dev/null
> ```

### 4.2 添加软件源

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
```

**检查写对没有：**

```bash
cat /etc/apt/sources.list.d/ros2.list
```

应该输出一行，末尾是 `noble main`。**版本代号必须和你的系统一致。**

```bash
sudo apt update
```

**看到什么算成功：** 输出里有 `Hit:...mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu`，且**没有** `NO_PUBKEY` 或 `404` 报错。

## 六、验证 ROS 2 装好了（第一个里程碑）

**开两个 Ubuntu 终端窗口**（在 Ubuntu 里按 `Ctrl+Shift+T`，或直接再打开一个）。

**窗口 A：**

```bash
ros2 run demo_nodes_cpp talker
```

**窗口 B：**

```bash
ros2 run demo_nodes_cpp listener
```

**看到什么算成功：**
- 窗口 A 不断刷 `[INFO] [talker]: Publishing: 'Hello World: 1'`
- 窗口 B 不断刷 `[INFO] [listener]: I heard: [Hello World: 1]`

✅ **这一步成功 = ROS 2 装好了。** 按 `Ctrl+C` 停掉两个程序。

> **为什么会成功（答辩素材）：** 这是 ROS 2 的发布/订阅（Publisher/Subscriber）通信模型演示。
> talker 节点向话题（Topic）发布消息，listener 节点订阅同一话题接收消息，
> 两者互不知道对方存在，通过 DDS 中间件解耦——这正是 ROS 2 多节点系统的核心机制，
> 也是我们导航系统中各模块（感知/规划/控制）之间通信的基础。

## 八、编译并启动本仓库工程（🎯 真正的第一个里程碑）

把仓库 clone 到 **Linux 原生文件系统**（不要放 `/mnt/c`、`/mnt/d` 下）：

```bash
cd ~
git clone https://github.com/Chen313424/WHC.git smart_community_ws
cd ~/smart_community_ws
```

编译：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

启动社区场景：

```bash
ros2 launch community_nav sim.launch.py
```

**看到什么算成功：**
1. 终端里出现 `Successfully spawned entity`，Gazebo 窗口弹出 4.2m×4.2m 社区场景 + 机器人
2. 另开终端自检传感器数据：

```bash
ros2 topic hz /scan            # 激光雷达（360°）
ros2 topic hz /odom            # 里程计
ros2 topic hz /camera/image_raw  # 相机图像
```

3. 三条命令都能持续刷出频率数字 = 仿真 + 桥接 + 机器人传感器全通。

> **为什么 `--symlink-install`（答辩素材）：** 它把 `install/` 里的文件做成指向 `src/`
> 的符号链接，改 launch/xacro/sdf/yaml 后**不需要重新编译**就能生效，
> 调参联调时能省掉大量重复编译时间。

## 十、常见坑速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `sudo` 输密码没反应 | Linux 正常行为 | 盲打完回车 |
| `NO_PUBKEY` | GPG 密钥没导入成功 | 重做 §4.1，检查密钥文件大小是否 > 0 |
| `apt update` 报 404 | 源里的版本代号和系统不匹配 | `cat /etc/apt/sources.list.d/ros2.list` 核对是 `noble` |
| `ros2: command not found` | 环境变量没生效 | `source ~/.bashrc`，检查 `echo $ROS_DISTRO` |
| Gazebo 黑屏/闪退 | WSLg 图形问题 | `export LIBGL_ALWAYS_SOFTWARE=1` |
| Gazebo 卡顿严重 | 软件渲染 | 关掉 Windows 侧其他占 GPU 的程序；降低 Gazebo 分辨率 |
| RViz 显示 "no tf data" | 仿真没启动或时钟没同步 | 确认仿真在跑；加 `use_sim_time:=True` |
| 编译报文件权限/速度极慢 | **工程建在了 `/mnt/c`、`/mnt/d` 下** | 见下一条 |

### ⚠️ 最重要的一条：工程必须放在 Linux 文件系统里

**不要在 `/mnt/c`、`/mnt/d` 下建 ROS 工程！**

```bash
# ❌ 错误：跨文件系统，编译极慢，权限和符号链接会出问题
cd /mnt/d/project

# ✅ 正确：放在 Linux 原生文件系统
mkdir -p ~/smart_community_ws/src
cd ~/smart_community_ws
```

> **为什么（答辩素材）：** WSL2 访问 Windows 文件系统（`/mnt/c`、`/mnt/d`）是通过 9P
> 网络文件系统协议转发的，I/O 性能只有原生文件系统的十分之一左右，
> 且不完整支持 Linux 文件权限和符号链接。ROS 2 的 `colcon build` 会产生大量
> 小文件读写，放在 `/mnt/d` 下编译时间可能从 1 分钟变成 20 分钟，甚至直接失败。

**代码备份**：用 `git` 提交到 GitHub/Gitee，或者定期 `cp -r ~/smart_community_ws/src /mnt/d/backup/`。
